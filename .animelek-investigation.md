# AnimeLek investigation

Sources inspected on 2026-09-04:
- https://animedar.net/
- https://animedar.net/anime-p/
- https://animedar.net/anime-p/koukaku-kidoutai-tv/
- https://www.animedar.net/wp-content/themes/animestream/assets/js/jqu.js?ver=1.0.49

Findings:
- Current AnimeLek domain is `animedar.net`, and series URLs are `/anime-p/<slug>/`.
- Listing HTML uses `<article class="bs">` with `.bsx > a[href*="/anime-p/"]`, title in `.tt h2`, and cover in `img.ts-post-image` `src`; pagination is `/anime-p/?page=2`.
- Detail cover is `img.ts-post-image` and currently resolves through `https://i*.wp.com/animedar.net/...`.
- Detail pages do not contain episode links under `/episodes/`. Episodes are rendered by site JavaScript: `#ServerList1 .divv11` is one episode group; `#EpList1 .CSB` contains labels (`الحلقة 1`, etc.).
- Each episode group contains server `<li>` values with `class`/`type` (`videa`, `asnwish`, `mp4upload`, `4shared`), `quality-data`, and a custom `data` attribute (not `data-*`). Example Videa data `MKu1lR5wMYgZHUlp`; website JS turns it into `https://videa.hu/player?v=MKu1lR5wMYgZHUlp`.
- Browser dynamic test confirmed clicking `IDSB1` then `.videa` creates iframe `https://videa.hu/player?v=MKu1lR5wMYgZHUlp`.
- Existing `ArabicVideoParser` expects cards `.anime-card/article.bs` but requires a link containing `/animes/` for non-animedar and currently only extracts `/episodes/`, so it misses AnimeLek's current card/detail structure and returns no chapters.
- Existing app `AnimeStream` contract expects direct HLS/MP4 URLs, not iframe URLs. `AnimePlayerActivity` uses Media3/ExoPlayer.
- Peer parsers Anime3rb/AnimePhoenix/RistoAnime parse site-specific cards, episodes, covers, and direct streams.
